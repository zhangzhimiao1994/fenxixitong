## 评测方法

1. **结构维度**（d1–d7、d9）：两名独立评审各自对照 darwin rubric 阅读 SKILL.md 打分，取平均。
2. **实测维度 d8（权重 23）**：每轮由执行 agent 严格按 skill 回答固定测试题（每个 skill 取 p1 + e1，hub 取 3 题），真实运行 `tools/divine.py`。与同一批不带 skill 的基线回复随机标成 out1/out2 盲评，两名评审各给 1–10 分；d8 取带 skill 回复的平均分。
3. 总分 = Σ(维度分 × 权重) / 10；每个 SKILL.md 篇幅 ≤ 基线 commit `58c7fd5` 的 150%。
4. 评审间噪声约 ±1.5 分。评审对"全部 9 分"的文档给出 90.0，很少给 10 分，因此 90 分要求两名评审在所有维度、所有回复上同时给 9 分以上。

## 主要改进（按影响排序）

1. **不再空停**：排盘需要核对时，同一轮给完整解读，末尾请用户核对；只有日期不确定或用户说盘不对才硬停。
2. **工具可信**：
   - `divine.py` 修复：`bazi --lon` 时漏打印四柱。
   - `astro` 行运新增容许度（"差 X°"）。
   - 回复里附 1 行工具原始输出，并说明"不是模型挑的"。
3. **安全与温度**：
   - 危机话术四要素：接住、评估、热线、留下。
   - 固定拒绝话术前先共情。
   - 投资问题直说"全部积蓄 = 高风险"，不给投或不投的倾向，附可直接发给朋友的话。
4. **一致性**：
   - hub 只保留一张深度表管条数和篇幅。
   - 选阵规则只保留在 draw-protocol。
   - 时辰模糊规则在 hub 和八字之间统一。
   - 牌义收尾与抽牌协议一致。
5. **架构**：紫微、周易、星盘、八字的来源考证和查表移入各自的 `references/`；子 skill 的顶层镜像副本已同步。
