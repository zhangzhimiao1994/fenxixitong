# 托勒密行星状态评估（Planet Condition）

## 🧭 决策树

```
用户提到星盘里的某颗行星 / 想用"古典规则"看盘
│
├── 没有出生日期？ → ❌ 回 fortune 路由（周易 / 塔罗）
├── 只问三要素、土星回归、今年行运？ → ❌ astrology-transit
├── 问寿命、疾病、事故、择日？ → ❌ 拒绝该部分（fortune 第五节），其余照常
├── 问"某个生活主题"（职业/财富/朋友）？ → ↪ ptolemy-topic-ruler（它会回调本 skill 第 3-6 步）
├── 问"我是什么性格"？ → ↪ ptolemy-mind-temperament
│
└── 有日期（最好有时间 + 城市）+ 想知道某颗/哪颗行星"有没有力" → ✅ 本 skill
    ├── 有精确时间 + 城市 → 全流程（含宫位强弱、昼夜派别）
    └── 只有日期 → 只做星座尊贵（第 3 步），跳过宫位与派别，注明精度不足
```

## 📥 输入与证据假设

- **数据来源**（禁止心算行星位置）：`python tools/divine.py astro YYYY-MM-DD HH:MM --tz 8 --lat 纬度 --lon 经度`（回归黄道 + 整宫制，输出各行星黄经与上升）；或用户从排盘软件粘贴。
- 工具**不给**：中天精确度数、逆行状态、界（terms）。处理：中天用第 10 宫星座近似并注明；逆行/速度若用户软件有就用，没有就写"未核对"；界只在用户软件提供时计入。（原书界表在本扫描本 OCR 中无法可靠辨认，PAGE 61-64，故不内置。）
- 回归黄道与托勒密一致：他明确规定星座从二分二至点起算（卷一第 25 章，PAGE 65）。
- 证据假设：这是**古典象征规则的内部一致应用**，不是经验验证过的预测；现代科学不支持占星预测效力（Carlson 1985, *Nature*；Dean & Kelly 2003）。

## 📖 RIA+E+B

### R — 原文位置与转述

- 卷一第 4-5 章（PAGE 41-42）：每颗行星按冷热干湿定性；热与湿"滋养、生发"，冷与干"消耗、离散"，由此木、金、月称吉，土、火称凶，日、水随联结对象而定。
- 卷一第 7 章（PAGE 43）：土星被分到白天、火星被分到夜里——不是同气相投，而是**用相反性质去调和**它们的过度（白天的热抵消土星的冷，夜里的湿抵消火星的干）。
- 卷一第 13 章（PAGE 50）：星的作用遇到同性质的体质更强，遇到相反性质就被"调和、削弱"。
- 卷一第 16 章（PAGE 52-54）：三分、六分在同性别星座之间，称"和谐"；四分、对冲在异性别星座之间，称"不和谐"。第 19 章（PAGE 55）：相隔一个或五个星座的"背过身"，没有亲和。
- 卷一第 26 章（PAGE 65-66）：一颗行星在所处位置同时拥有两种以上亲和关系 = "战车/宝座"，力量特别增强；处在与自己不相似的位置，影响"大量散失"。
- 卷一第 27 章（PAGE 67）：东方、快速、顺行时"it has then its greatest power"；西方、迟缓、逆行则减弱；在中天及其后宫最强，在上升线上或其后宫也有力；在地平线下又与上升无相位者"几乎失效"。
- 卷三第 4 章（PAGE 105）把以上浓缩为两层：**宇宙层**（在自己的位置、东方、快速 = 强）与**盘面层**（角宫、续宫，尤其上升与中天 = 强；果宫 = 弱）。

### I — 白话解释

托勒密不问"这颗星好不好"，而问"**它此刻有没有条件把本性发挥出来**"。滋养型行星失去条件，好意会打折；张力型行星有了条件（在主场、被昼夜调和），它的冷或干会变成纪律、决断，而不是单纯的阻碍。判断分三层：本性（是什么）→ 尊贵（在不在自己的地盘）→ 强弱（显不显眼、发力早不早）。

### A1 — 书中应用（转述）

- 卷三第 3、4 章（PAGE 102-105）：选主宰星时，按庙、三分性、旺、界、相位"五种权利"计数，权利最多者胜——尊贵体系在全书的实际用途就是**投票选代表**。
- 卷三第 18 章（PAGE 137-141）：同一颗木星，"得位"时慷慨、虔敬，"失位"时变成挥霍、偏执——状态决定同一本性的高低版本。
- 卷四第 4 章（PAGE 151-152）：职业主宰星东出或在角宫 → 有地位与主导权；西入或在果宫 → 处于从属位置。

### A2 — 未来触发场景

1. "我听说我的火星落在巨蟹是'落'，是不是很糟？" → 第 3-6 步：火星在巨蟹为落，但若是夜生（火星本属夜）、又在角宫，古典规则会说"冲动被收着、绕着表达"，并非单向的坏。
2. "我盘里哪颗星最有力？" → 对七颗行星逐一做第 3-5 步，选"尊贵 + 显眼度"都高的那颗，作为"盘的发言人"。
3. "土星在我的上升，是不是一辈子不顺？" → 第 4 步派别：昼生则土星被调和；结论用"结构感、慢热、责任感"而非"不顺"。

### E — 执行步骤

1. **取数据**：按"输入"运行工具或请用户粘贴；原样展示一行：`☉__ ☽__ ☿__ ♀__ ♂__ ♃__ ♄__ ↑__（整宫制）`。
2. 🔴 **CHECKPOINT 1（数据核对）**：出生日期不确定或用户说盘不对 → 停下核对，不解读。只有日期无时间 → 跳过第 4 步昼夜判断里依赖上升的部分和第 5 步宫位，注明"未读宫位"。
3. **尊贵计数**（查上表）：对目标行星列出它在所处星座拥有的权利：庙 / 三分性（按昼夜取主）/ 旺 / 界（仅当软件提供）/ 与该星座主星的和谐相位（整宫：相隔 2 或 4 个星座）。另记是否在"落"。
   - ≥2 项 → **主场**（战车）；1 项 → **有依托**；0 项 → **客场**；在落 → **逆风**。
4. **昼夜派别**：用度数算，不用整宫宫号——(上升度数 − 太阳黄经) 取 0-360，落在 0-180 之间 = 太阳已升起 = 昼盘，否则夜盘；结果离 0 或 180 不到 5° 时写"派别临界，不下结论"。行星派别与盘一致 → "被调和/顺势"；土星在夜盘、火星在昼盘 → "未被调和，张力更直接"。
5. **强弱**：
   - 宇宙层：行星黄经落后于太阳 15-180°（先于太阳升起且可见）= 东方/晨出 → 发力早而强；领先太阳 = 西方/昏入 → 较弱较晚；与太阳相距 <15° = "在太阳光下"（卷二第 7 章 PAGE 83 也把它列为削弱条件）→ 写"被太阳盖住，独立表现弱，风格并入太阳主题"。逆行/速度：有数据才写。
   - 盘面层：第 1、10 宫 = 最显眼；第 4、7 宫 = 角宫次之；第 11、2、5、8 宫 = 续宫；其余 = 果宫。地平线下（用第 4 步同一算法：(上升 − 行星) 取 0-360 落在 180-360）且与上升星座无相位 → "很少显现"。
6. **相位（整宫）**：与其他行星相隔 2/4 个星座 = 和谐，3/6 = 张力，1/5 = 不合；只报与滋养型、张力型行星各最多 1 组。
7. 🔴 **CHECKPOINT 2（语言转换）**：把"凶/吉/落/失效"全部过一遍 `fortune` 第三节转换表与下方对照：吉星→滋养型，凶星→张力型，落→逆风，失效→"不太显现"。任何"注定、必然、会出事"的句子删掉。
8. **合成一句状态判词**：`本性 + 场地 + 显眼度 → 这股倾向更容易以 ___ 的方式表达`，再给 1 个与之对应的最小行动。

### B — 边界

- **没有经验效力**：所有判词都是"这套古典规则认为"，现代科学不支持占星预测；不能用来做健康、法律、投资、婚育决定。
- **作者自己的边界**：托勒密在 I.25（PAGE 64-65）把更细的"度位"划分斥为"科学的虚荣"——本 skill 不扩充十度面、恒星逐颗、阿拉伯点等后世细分。
- 托勒密的"面"(face)是行星与日月的角距关系（I.26），不是后世的 10° 十度面；不要混用。
- 原书的"凶星"在派别、尊贵都好时可以很有建设性；**禁止**把张力型行星直接说成"倒霉""克"。
- 不评外貌、不推疾病（卷三第 16-17 章的形体与伤病内容一律不用）。
- 精度：没有出生时间时，宫位、昼夜派别、东西方（部分）都不可靠，必须明说。

## 💬 输出格式

自然段落，≤350 字，按序：
1. 一行盘面（来源 + 精度）
2. 目标行星的"本性 + 场地 + 显眼度"三句（术语最多 2 个，括注白话）
3. 一句合成判词（倾向语言）
4. 1 个最小行动
5. 结尾："这是托勒密古典规则的象征读法，现代研究不支持它的预测力；选择在你。" + 唯一一个问题（核对时间/城市，或"想看哪个生活领域？"）

**示例**（1990-01-08 07:30 上海，问土星；工具实际输出）：
> 盘面（工具排盘，回归黄道 + 整宫制）：土星摩羯 16.4°，太阳摩羯 17.4°，上升摩羯 25.8°。土星在摩羯是"入庙"（在自己家），落在第 1 宫最显眼的位置；太阳刚升起，是白天出生，而土星本属白天，被调和得比较顺。但它离太阳只有 1°，按托勒密的说法算"在太阳光下"，独立表现会被太阳的主题吸收。合起来，这套古典规则会说：你的严谨、慢热、重承诺，不太单独冒头，而是融进"我要成为什么样的人"里，常表现为对自己要求很高。这一周可以试一件事：把一项拖了很久的长期计划拆成 4 周、每周一步。这是古典规则的象征读法，现代研究不支持它的预测力，选择在你。07:30 是出生证明上的时间吗？
