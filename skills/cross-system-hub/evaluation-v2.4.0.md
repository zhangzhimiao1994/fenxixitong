## 本轮改进详情（v2.3.0 → v2.4.0）

### dim2 工作流清晰度（9→10）

**改进前**: 7个STEP有输入/输出/前置条件，但无统一数据流格式
**改进后**: 每个STEP增加结构化数据流
```
输入: {...}
  ↓
处理: ...
  ↓
输出: {...}
```
- STEP 1: activation_matrix 数据流
- STEP 2: priority_ranking 数据流
- STEP 3: system_analysis 数据流
- STEP 4: crosswalk 数据流
- STEP 5: tension_points 数据流
- STEP 6: synthesis + resonance_core 数据流
- STEP 7: integrated_actions 数据流

### dim3 失败模式编码（9→10）

**新增 fallback**:
- **C6**: 用户质疑体系适用性（"我不信中医""心理学骗人"）→ 不辩护，重新框架，提供替代
- **C7**: 单体系分析严重跑偏 → 自检，坦诚，追问，修正，记录局限

**C1-C7 覆盖场景**:
| Fallback | 场景 | 处理方式 |
|----------|------|---------|
| C1 | 输入信息不足 | 追问模板 |
| C2 | 体系激活歧义 | 轻量分析+标注 |
| C3 | 体系冲突无法调和 | 阶段化方案 |
| C4 | 用户认知超载 | 降级到L1 |
| C5 | 紧急危机信号 | 停止分析+资源 |
| C6 | 用户质疑体系 | 不辩护+替代方案 |
| C7 | 单体系分析跑偏 | 自检修正+记录局限 |

### dim7 整体架构（9→10）

**新增 J 章节：跨 Runtime 兼容性**
- 支持 runtime 矩阵（OpenClaw主/子Agent/LLM/本地阅读器）
- 子 Agent 调用链规范（5个子Agent并行→主Agent汇总）
- 单 Agent 模式说明（当前默认）
- 版本兼容性表
