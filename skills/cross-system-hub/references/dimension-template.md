# 新增维度模板（cross-system-hub 参考）

目标：加一个维度 = 新建一个入口 skill + 在总入口维度表加一行。总入口的其他段落都按"层"和维度表的列来写，不用改。

## 一、归层判据（先定层，再定写法）

- **观察层**：依据用户陈述的事实解释"为什么会这样、卡在哪一环"，结论能被用户的经历核对；可以定主要矛盾。
- **校准层**：不产生新结论，只把已有判断改写成"事件 + 截止日 + 判定方式 + 几成把握"并设复盘点；不定主要矛盾。
- **象征层**：需要取数（抽、排、起）或用户报数据，只提供视角、节奏和镜子；不推翻事实、不定主要矛盾、不给确定预言，⚖️ 时只读心态。

## 二、新增维度的步骤（≤11 步）

1. 从蒸馏产物（`distill/<书>/`：R 来源、I 方法论、A 应用、E 执行步骤、B 边界）建子 skill，每个子 skill 顶部第一行写："> 被维度入口或总入口调用时，只提供素材；格式、篇幅、提问、收尾、危机话术按总入口全局契约。"
2. 新建入口 `skills/<入口名>/SKILL.md`：frontmatter 单行合法 YAML（name、description、version），正文最前面放下面第三节的段落契约，再放子 skill 路由表、失败处理、边界、反例。
3. 按第一节判据定层；象征层入口要写清取数命令，以及深度表"最小 / 标准 / 最大"三档各对应什么。
4. 填段落契约：只写"包含什么"，篇幅只用"约几成 / 1 句"，不写字数，不自己定问句（只列候选问题和它的级别 ①–⑤）。
5. 在总入口维度表加一行：维度 | 层 | 入口 | 激活信号 | 完整条件（写成"满足什么就完整"的整句）| 取数对象（象征层写数据从哪来：心态或状态 / 一件具体的事 / 出生信息，其他层写"—"；C10、三周计划按这一列自动选维度）| 顺序 | 候选问题。顺序数字决定同层内的书写先后，可以用小数插在两个现有维度之间（如 4.5）。
6. 在 `translation-and-plan.md` 第一节互译表加一列；暂时没有对应时整列写"—"，或先不加列（缺列时该维度不参与共振）。
7. 张力表（同文件第六节）里有和已有维度的固定冲突时加一行；没有就不加。
8. 给新入口写 `test-prompts.json`，至少 2 条（1 条单独触发、1 条和已有维度同时出现走总入口）。
9. 新入口或子 skill 用到抽牌/排盘工具时，运行 `python tools/sync_scripts.py`：把工具和依赖清单打包进该 skill 的 `scripts/`，并写入"运行抽牌/排盘工具"标记块；再运行 `python tools/sync_scripts.py --check`，必须 0 差异。
10. 运行 `python tools/check_skills.py`（Windows 用解释器全路径），必须 0 错误；它会自动读维度表的新行，检查入口存在、含段落契约、没有字数配额，"层"只取观察/象征/校准，"顺序"是数字且不重复，互译表列名都在维度表里（缺列只警告），以及工具包是否齐全。
11. 不改总入口的其他段落；如果发现非改不可，说明那一段还在逐个点名维度，先把它改成按层或按列写。

## 三、段落契约空白模板（与现有 9 个入口同一结构）

```
## 被总入口调用时：段落契约

- 输入：从总入口拿到什么（用户原话、工具输出、深度等级、本段是完整还是一句带过）
- 本段必须包含：
  1. …（写"包含什么"，不写"照抄这句"）
  2. …
- 一句带过时写什么：…
- 篇幅：完整约占全文 1 成（主要矛盾在本维度时约 1.5 成）；一句带过 1 句——不写字数
- L1 保留：L1 时只留哪几项，并成 1–2 句
- 可提交的候选问题：[级别] …（交给总入口的唯一问题表，不自己问）
- 本段禁止：…（至少含：再引主要矛盾段引过的原话、做法、免责句、评论方法本身）
- 本维度特有的失败分支：如果 X → Y
- 选用哪些子 skill：…（指针）
- 格式、篇幅、提问、收尾、危机话术：见总入口全局契约（单独使用时也一样）
```

入口的"单独使用时"一节末尾写一句指针："总入口里只剩本维完整时不转到这里，见总入口 STEP 1。"

可选：入口需要占用行动名额时，在"篇幅"一项末尾写"完整时占 1 个步骤"；有一句常识性提示需要留在段落里时，在"本段必须包含"里注明"这一句是常识提示，不算步骤"。

跨入口条款不用改：`guanxi` 的"各层的边界"、C10、组合命中表、三周计划都按"层"或"取数对象"列写；`check_skills` 会对段落契约里点名其他维度中文名的地方给警告。
