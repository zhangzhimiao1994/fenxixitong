# 解结通滞法

## R — 原文 (Reading)

> 一经上实下虚而不通者, 此必有横络盛加于大经, 令之不通。
> 视而泻之, 此所谓解结也。
> 上寒下热, 推而上之; 上热下寒, 引而下之; 大热遍身, 推而散之。
> 夫善用针者, 取其疾也, 犹拔刺也, 犹雪污也, 犹解结也, 犹决闭也。
>
> — 黄帝/岐伯, 刺节真邪第七十五、九针十二原第一

---

## I — 方法论骨架 (Interpretation)

解结通滞法是一个识别系统阻塞点并精准疏通的问题解决框架。

1. **找到"横络": 阻塞的真正原因**: 系统不通往往不是整条链路都有问题, 而是"横络盛加于大经"——某个交叉点的压迫/阻塞导致了全线不通。找到这个点, 问题迎刃而解。

2. **诊断方法: 切而循之**: "用针者, 必先察其经络之实虚, 切而循之, 按而弹之, 视其应动者乃后取之"——通过沿线路逐一排查, 找到响应异常的点。



   🔴 **CHECKPOINT**: 在进入下一步之前，将分析结果展示给用户，等待确认后再继续。
3. **方向性疏通**: 阻塞有不同的方向模式——上寒下热(推而上之)、上热下寒(引而下之)、大热遍身(推而散之)。疏通不是无方向的, 必须判断阻塞的方向性。
   🛑 **STOP**：请确认上一步的分析结果后再继续。


4. **四喻定位**: 拔刺(精准取出)、雪污(清除污染)、解结(打开死结)、决闭(疏通堵塞)——不同性质的阻塞用不同的疏通方式。

## A1 — 书中的应用 (Past Application)

### 案例 1: 一经上实下虚的解结
- **问题**: 一条经脉上部充实下部空虚, 气血不通, 是什么原因?
- **方法论的使用**: 不是经脉本身的问题, 而是"横络盛加于大经"——有一条横向的络脉压迫了主通道。解法: "视而泻之"——找到压迫点, 在那里泻除多余的压迫。
- **结论**: 阻塞往往来自意料之外的第三方因素(横络), 而非主通道本身的问题。
- **结果**: 在压迫点精准疏通后, 主通道自然恢复通畅。

### 案例 2: 上寒下热的推而上之
- **问题**: 上半身寒下半身热, 如何处理?
- **方法论的使用**: "先刺其项太阳, 久留之, 已刺则熨项与肩胛, 令热下合乃止, 此所谓推而上之者也"——在颈部(上方的控制点)干预, 将热量推向上部。
- **结论**: 不是在寒的地方加热, 而是在控制点(颈部)操作, 通过调节"阀门"来分配资源。
- **结果**: 通过控制点调节, 实现上下温度重新平衡。

## A2 — 触发场景 (Future Trigger) ★

1. **流程阻塞**: 工作流程/信息流/决策链中某个环节堵塞, 导致上下游失衡。
2. **资源错配**: 系统一端资源过剩另一端不足, 但不是总量问题而是流通问题。
3. **久拖不决**: 问题长期存在, 局部修复无效, 可能是某个隐藏的瓶颈。

### 语言信号

- "到处卡住了"
- "上面太多了下面不够"
- "某个环节堵住了整个流程"
- "直接修不好, 需要另想办法"

## E — 可执行步骤 (Execution)

### 模板：阻塞诊断表

| 检查项 | 你的回答（选项） | → 自动判定 |
|--------|---------------|-----------|
| 阻塞是全系统还是方向性的？ | 全线不通（所有事都推不动） / 方向性（有的方向行有的不行） | 全线不通→全面淤滞；方向性→上下虚实排查 |
| 如果是方向性，哪端实哪端虚？ | 上实下虚（上面很堵下面很空） / 上虚下实（上面空下面堵） / 不清楚 | 上实下虚→引而下之；上虚下实→推而上之 |
| 具体卡在哪个节点/环节？ | [具体环节名称] | → 定位阻塞点（横络） |
| 这个节点卡住的表现是？ | 完全不响应 / 响应极慢 / 时通时堵 / 输出异常 | → 阻塞严重程度 |
| 有没有可以绕行的路径？ | 有替代路径 / 可以局部绕行 / 没有 | 有替代路径→先绕行再回头疏通；没有→直接疏通 |
| 之前试过哪些疏通方法？效果如何？ | [方法1：效果] / [方法2：效果] | 直接疏通失败→需另辟蹊径（远道刺/巨刺） |

**推导规则**：第 1-2 项决定疏通方向（推而上/引而下/推而散），第 3-4 项定位阻塞点，第 5-6 项决定疏通策略（直刺/绕行/远道）。

### 步骤

1. **填表定位**：输出 `阻塞模式：[全线/上实下虚/上虚下实] | 阻塞点：[X] | 严重度：[完全/部分/间歇]`
2. **选择疏通方向**：上寒下热→推而上之；上热下寒→引而下之；全面淤滞→推而散之。给出具体疏通动作。
   🔴 **CHECKPOINT**：展示诊断+疏通方向，等待确认。
3. **执行疏通**：输出 `疏通入口：[X] | 方法：[直通/绕行/远道] | 预期变化：[Y]`
4. **设定验证指标**：疏通后应有可感知的变化（如"热下合乃止"）。没变化 → 定位可能错误，重新排查。设复查点：`[N小时后/每天] 检查 [具体指标]`

## B — 边界 (Boundary) ★

### 不要在以下情况使用

- **资源绝对不足**: 如果问题不是阻塞而是总量不够(如预算不足), 疏通无法解决——需要增加资源而非疏通。
- **结构已毁**: "脉血结于中中有着血, 血寒故宜灸之"——有些阻塞已经造成结构性损伤, 单纯疏通不够, 需要修复。

### 失败模式

- **定位错误**: 在错误的位置疏通, 不仅无效还可能制造新的阻塞。
- **过度疏通**: 疏通后继续操作, 导致系统从"阻塞"变为"泄漏"。

### Fallback（if-then 三段式）

| 触发条件 | 一线修复 | 仍失败 → 兜底 |
|---------|---------|-------------|
| 疏通阻塞后问题反而加重 | 立即停止。这可能是代偿反应——阻塞其实是系统为维持平衡制造的假性阻塞。回到步骤1用上下虚实关系重新定位 | 重新定位后仍然找错 → 不继续疏通。先稳全局：确保系统整体不崩，再花时间慢慢找真正的阻塞点 |
| 系统同时出现「上实下虚」和「上虚下实」的矛盾判断 | 区分时间先后：先出现的是哪个方向？按先发方向处理 | 时间先后也分不清 → 系统可能整体紊乱。先稳全局（不做任何定点疏通），观察 2 周后再判断 |
| 阻塞位置不可操作（在外部环境/他人身上） | 不硬攻不可控节点。找间接路径：对可操作的上游或下游施加影响，让变化传导到阻塞点 | 上下油都不可操作 → 承认此阻塞超出能力范围。要么改变目标，要么等待外部条件变化 |
| 疏通后局部好转但全局恶化 | 典型的「通了一个口子，其他地方压力暴增」。立即暂停，检查上下游压力分布变化 | 全局恶化不可逆 → 可能一开始就不是阻塞问题，而是系统的容量上限问题。考虑 `scale-and-restraint-control` |
| 反复疏通反复堵 | 不是疏通手法的问题，是上游源源不断在制造阻塞。追到上游源头：「是什么在持续往这里灌东西？」 | 上游也找不到 → 考虑结构性改造：不是通路的问题，是整个管网设计有问题 |
| 不区分结构性和功能性阻塞 | 结构性 = 路断了需修路（架构变更/组织调整）。功能性 = 路堵了需疏导（流程优化/资源调配） | 分不清 → 先按功能性处理（成本低、风险小），如果 2 周没改善 → 按结构性处理 |

## 反例黑名单（dim9）

| # | 不要做的事 | 为什么 | 正确做法 |
|---|-----------|--------|---------|
| 1 | 直接在阻塞点猛攻——越用力越堵 | 阻塞点本身已经没有通路，正面冲击只会加重症状 | 先在阻塞点的上游减负或下游疏通，通过间接传导化解阻塞 |
| 2 | 把"上实下虚"和"上虚下实"混为一谈 | 两个方向完全相反，用错方向会让问题恶化 | 必须判断方向：上面堵下面空？还是上面空下面堵？方向判断错了全盘错 |
| 3 | 疏通后发现问题加重仍不回头 | 可能是代偿反应——你以为的阻塞其实是系统为了维持平衡而制造的"假性阻塞" | 疏通后问题加重 → 立刻停止，回到上下虚实关系重新定位 |
| 4 | 硬攻不可控的阻塞点（外部环境/他人行为） | 把精力花在不可控节点上是浪费 | 找间接路径：对可操作的上游/下游节点施加影响 |
| 5 | 不区分"结构性阻塞"（需要重建路径）和"功能性阻塞"（需要调整节奏） | 结构性阻塞 = 路断了需要修路；功能性阻塞 = 路堵了需要疏导 | 先判断：是系统结构问题还是运行节奏问题？不同阻塞不同解法 |
