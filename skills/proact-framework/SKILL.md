# ProACT 决策框架

**来源**: Hammond, Keeney & Raiffa, *Smart Choices* (1999), Ch 1 | 三位哈佛商学院决策科学学者 100+ 年研究精华

---

## 触发条件

**应该触发**：
- 用户说"我不知道该怎么选""这个决定太难了""帮我分析一下"
- 用户面临需要结构化分析的复杂决策
- 用户在做选择时感到焦虑、纠结、迟迟不能决定

**不应触发**：
- 问题已有明确答案
- 纯粹信息查询
- 需要专业知识而非决策方法的问题
- 用户只有一个方案且不涉及选择（改用 `risk-profiles` 评估不确定性）

---

## 核心模型：PrOACT 八要素

```
Problem   → 定义正确的决策问题
    ↓
Objectives → 厘清你真正想要什么
    ↓
Alternatives → 创造更好的备选方案
    ↓
Consequences → 描述每个方案的后果
    ↓
Tradeoffs → 在冲突目标之间做权衡
    ↓
[Uncertainty] → 处理不确定性（需要时）
    ↓
[Risk Tolerance] → 评估风险承受度（需要时）
    ↓
[Linked Decisions] → 规划未来的联动决策（需要时）
```

前五个（PrOACT）是核心，适用于几乎所有决策。后三个是扩展，适用于涉及不确定性或未来规划的复杂决策。

## 执行序列

### Step 1: 定义问题（Problem）

> "一个好的解决方案解决正确的问题，比一个完美的方案解决错误的问题要好得多。"

**关键动作**：
1. 写下你认为的问题是什么
2. 问：是什么触发了这个决策？为什么我在考虑它？
3. 挑战你的假设：有没有更根本的问题？
4. 重新表述问题，至少用三种不同的方式

**陷阱**：最常见的错误是把问题定义得太窄。例如"我该换哪辆车？"vs"我该如何满足出行需求？"

### 🔴 CHECKPOINT 1：问题定义确认

**向用户展示你理解的问题定义，确认后再继续。** 如果用户说"不对"→ 重新定义。如果用户说"对但..."→ 从 Step 1 重新开始调整范围。如果用户说"我还是不确定"→ 终止框架分析，转用 `problem-definition` skill 做深度问题定义。

### Step 2: 厘清目标（Objectives）

> "如果你不知道要去哪里，任何路都能带你到达。"

**关键动作**：
1. 写下所有你关心的东西（愿望清单）
2. 问"为什么"直到触及根本——区分"手段目标"和"根本目标"
3. 把每个关注点转化为"动词+对象"格式（如"最小化通勤时间"）
4. 确保目标列表完整：考虑短期/长期、硬性/软性、对自己的影响/对他人的影响

### 🔴 CHECKPOINT 2：目标清单确认

**向用户展示整理好的目标清单，逐条确认是否遗漏或多余。** 如果目标 > 8 个 → 合并相似目标，只保留根本目标。如果目标 < 2 个 → 确认是不是只有一个目标在起作用（如果是，决策简化为直接比较）。

### Step 3: 创造备选方案（Alternatives）

> "你的决策不可能比你的最佳备选方案更好。"

**关键动作**：
1. 先不要评价——尽可能多地列出方案
2. 问"还有没有别的办法？"
3. 考虑过程性方案（"先获取更多信息再决定"）
4. 挑战约束：哪些"必须"其实是"想要"？

### 🔴 CHECKPOINT 3：方案池确认

**向用户展示所有方案，逐一确认是否遗漏。** 如果只有 1 个方案 → 提示用户创造更多（"如果你不能选这个方案，你还能做什么？"）。如果方案 > 6 个 → 快速初筛，排除明显不可行的。如果"维持现状"不在列表中 → 主动加入。

### Step 4: 描述后果（Consequences）

> 建立后果表——行=目标，列=备选方案，每个格子用恰当的尺度描述后果。

**执行分流**：
- 目标 ≤ 3 个且方案 ≤ 3 个：在此 skill 内直接建简易后果表
- 更复杂 → 调用 `consequences-table` skill 获取完整后果表构建流程（含尺度选择指南、支配关系检测）

#### 简易后果表模板

| 目标 | 方案A | 方案B | 方案C | 现状 |
|------|------|------|------|------|
| (目标1) | | | | |
| (目标2) | | | | |
| (目标3) | | | | |

### 🔴 CHECKPOINT 4：后果表确认

**向用户展示填好的后果表（即使是简易版），确认数据准确。** 如果用户对某个格子的数值不确定 → 标记为"需核实"，判断是否值得花时间获取信息还是用估计值先继续。

### Step 5: 做权衡（Tradeoffs）

> 当目标冲突时，用等价交换法逐一消除目标。

**执行分流**：
- 建完后果表后只有一个方案被支配后仍剩余 > 1 个 → 调用 `even-swaps` skill 做等价交换
- 所有方案已被支配只剩 1 个 → 跳到 Step 6（如果有不确定性）或直接出结论
- 用户说"两个方案各有优劣哪个都不完美" → 直接调用 `even-swaps` skill

### Step 6: 处理不确定性（Uncertainty）

**执行分流**：
- 当前决策涉及不可控的未来变量（市场、他人行为、随机事件）→ 调用 `risk-profiles` skill 的 Part A（风险画像）
- 当前决策结果确定 → 跳过此步骤

**简易不确定性处理**（在此 skill 内）：
1. 列出最关键的 1-3 个不确定性因素
2. 对每个不确定性，快速估计最好/最差/最可能三种结果
3. 问：最好的结果值得为最差的结果冒险吗？

### 🔴 CHECKPOINT 5：不确定性评估确认

**如果简单决策中不确定性不显著 → 直接跳到结论。** 如果用户对不确定性感到焦虑 → 调用 `risk-profiles` skill 完整流程。

### Step 7: 评估风险容忍度（Risk Tolerance）

**执行分流**：
- 决策涉及显著的下行风险且用户表现出风险厌恶 → 调用 `risk-profiles` skill 的 Part B
- 决策下行风险可控或用户已有明确风险偏好 → 在此 skill 内快速评估

**快速风险评估**（在此 skill 内）：
- 问用户："最差的后果发生了——你能承受吗？你愿意承受吗？"
- 如果用户说"不能承受但概率很低" → 讨论风险缓解措施（分担、对冲、保险、信息获取）

### Step 8: 联动决策（Linked Decisions）

**执行分流**：
- 当前决策的未来后果取决于后续还要做的决策 → 在此 skill 内用简单决策树
- 简单线性决策（做完这个就不用再选了）→ 跳过此步骤

**简单决策树模板**：
```
当前决策 → 如果选A → 未来决策X1 vs X2
          → 如果选B → 未来决策Y1 vs Y2
```
向前看（推演未来分支），往回推（从未来最优反推现在该选什么）。

---

## 🔴 CHECKPOINT 6：最终结论确认

**完成后，向用户总结：**
1. 推荐方案是什么
2. 为什么推荐它（关键理由 2-3 条）
3. 最大的不确定性/风险是什么
4. **只呈现分析结果，不替用户做决定。** 如果用户说"我还是选另一个"→ 询问是什么目标/风险在驱动这个选择，确认没有被遗漏的目标。

## 分流决策树（快速路由）

用户说"我不知道该怎么选"时，用以下树判断从哪个要素开始：

```
用户有清晰的方案但不确定哪个好？
  ├─ 是 → 跳过 Step 1-3，从 Step 4 后果表开始
  └─ 否 → 从 Step 1 问题定义开始

用户只有一个方案，纠结"要不要做"？
  ├─ 是 → 这不是选择问题，改用 risk-profiles 评估
  └─ 否 → 继续完整框架

用户说"我纠结的是XX换YY值不值"？
  ├─ 是 → 直接到 Step 5，调用 even-swaps
  └─ 否 → 继续完整框架

用户说"我想好了但总觉得哪里不对"？
  ├─ 是 → 先跑 psychological-traps 检测，再回框架
  └─ 否 → 继续完整框架
```

## 失败编码表（if-then fallback）

| 卡点 | 触发条件 | 一线修复 | 仍失败 → 兜底 |
|------|---------|---------|-------------|
| **问题定义卡住** | 用户反复修改问题定义 > 3 次 | 调用 `problem-definition` skill 做深度定义 | 暂停分析，等用户想清楚再继续 |
| **目标清单一团乱** | 用户的目标彼此矛盾或表述模糊 | 用"为什么"追问，把手段目标转化为根本目标 | 接受列表现状，在权衡阶段自然会澄清 |
| **想不出备选方案** | 用户说"只有这两个方案"且不满意 | 问"如果这两个都不能选，你还能做什么？" | 考虑过程性方案（先收集信息再做决定） |
| **后果表某格不确定** | 用户说"这个我不知道" | 判断信息获取成本 vs 决策价值，低成本→获取，高成本→估计 | 用范围估计代替精确值（如"5000-8000 元"） |
| **权衡做到一半想放弃** | 用户说"算了太复杂了我就选直觉" | 提醒：直觉可能被心理陷阱影响，至少先跑 psychological-traps 检测 | 尊重用户选择，但标注"此决策未经完整权衡分析" |
| **不确定性太大** | 用户说"万一...怎么办"反复出现 | 切换至 `risk-profiles` skill 建立风险画像和容忍度评估 | 如仍无法决策，考虑"先获取更多信息"的过程性方案 |
| **框架分析跑不完** | 用户在中途失去耐心或决策不配这个复杂度 | 跳到十问诊断快速版，只做最关键的 1-2 个要素 | 承认"这个决策不值得完整分析"，切换到轻量模式 |

## 十问诊断（快速启动）

当用户不知从何开始时，依次问：

1. 我的决策问题是什么？
2. 我的根本目标是什么？
3. 我有哪些备选方案？还能想到更多吗？
4. 每个方案对各目标的后果如何？
5. 哪些目标之间存在冲突？哪里最需要权衡？
6. 哪些不确定性影响严重？
7. 我愿意承担多大风险？
8. 我有没有提前规划未来的联动决策？
9. 现在这个决策已经清楚了吗？还有什么保留？
10. 如果还不清楚，关键症结在哪里？

## 核心原则

1. **分割与征服**：复杂决策拆成8个要素逐一解决
2. **聚焦关键**：循环扫一遍所有要素，大部分决策只有1-2个要素是关键瓶颈
3. **积极主动**：不要等决策被强加给你——创造决策机会
4. **过程 > 结果**：好过程不保证好结果，但提高胜率

---

## 边界与限制

- 不替代专业知识（如医疗、法律、投资）
- 不处理纯直觉型决策（如紧急避险）
- 分析深度应与决策重要性匹配——不重要的决策不值得完整跑一遍

## 🚫 反例与黑名单（不要做的事）

| # | 反模式 | 为什么不要做 | 替代做法 |
|---|--------|------------|---------|
| 1 | **替用户做决定** | 框架是分析工具不是决策引擎，最终选择权在用户 | 说"根据分析，方案A在你的目标上表现最优"，不说"你应该选A" |
| 2 | **跳过问题定义直接进入方案比较** | 解决错误问题 = 浪费所有后续分析 | Step 1 + CHECKPOINT 1 不过不能进入 Step 2 |
| 3 | **只列两个方案就停止** | 好方案可能在你没想到的地方 | 至少列 3 个方案（含"维持现状"），不超过 6 个 |
| 4 | **忽视软性目标** | "幸福感""家庭和谐"比"成本""时间"更难量化但同等重要 | 软性目标用文字描述，不强行打分 |
| 5 | **为不重要的决策跑完整框架** | 选午餐吃什么不需要 8 要素分析 | 先用分流决策树判断复杂度，轻量决策用十问诊断快速版 |
| 6 | **在用户焦虑时强行推进分析** | 焦虑状态下认知能力下降，分析质量低 | 先做一项简单的（如只定义问题），降低认知负荷再继续 |
| 7 | **把框架当成"正确答案"** | 不同人对同一目标的价值判断不同 | 框架输出的是结构化的分析结果，不是唯一正确答案 |
