## 🧭 决策树

```
用户：被浅层事务淹没 / 下班停不下来
│
├── 需要的是"整块深度时间用哪种方式排" → ❌ deepwork-depth-philosophy
├── 时间有了但专注不住 → ❌ deepwork-embrace-boredom
├── 加班源于违法用工、欺凌，或已出现长期失眠、崩溃感 → ⚠️ 建议劳动/心理专业帮助；情绪为主 → psyche
├── 入门级岗位、完全由他人派活 → ⚠️ 只用步骤 4（停工仪式）与步骤 3 的轻量版
│
└── 有一定日程自主度 + 浅层事务挤压正事 → ✅ 激活
       ├── 说不清时间去哪了 → 步骤 1（量化深度）
       ├── 知道太多杂事但没有底线 → 步骤 2（预算 + 固定下班点）
       ├── 想安排好每天 → 步骤 3（时间块）
       └── 下班后脑子停不下来 → 步骤 4（停工仪式）
```

## 📥 输入与证据假设

**需要的输入**：
1. 上周（或典型一天）的事项清单与大致时长；
2. 岗位层级与自主度：能否拒绝会议、能否和上级谈工作配比；
3. 固定占用（会议、课、通勤、照护）；
4. 希望的下班时间与当前实际下班时间；
5. 下班后被工作侵入的主要入口（邮件、群消息、脑内反复）。

**证据假设**：
- 量化深度的"应届生月数"是作者设计的思想实验，用于排序，不是精确度量。
- 30%–50% 浅层比例是作者对多数非入门知识岗位的经验估计。
- 固定日程生产力来自作者与另一位教授（Nagpal）的自述，学术岗位自主度偏高。
- 停工仪式的研究依据：作者引用的无意识思考研究复现失败；注意力恢复研究效应温和；蔡格尼克效应与"做计划可释放注意"的稳健性近年存疑。可靠的部分是"每日深度上限有限、晚上补的多是低价值浅层工作"这一推理和作者的长期实践。要说"值得试"，不说"科学证明"。
- 人们普遍高估或低估自己的时间用途（书中引用的看电视、睡眠、工时自估偏差数据），这是做时间块的出发点。

## 📖 RIA+E+B

### R（Reading，转述）
- 浅层要封顶不是清零（PAGE 129–130）：工作离不开一定量浅层事务；每日深度上限约 4 小时，看似另一半时间可以随便用，但会议、课程、电话很容易把一天切到连这 4 小时都凑不出。作者一个普通教学日，3 段会议和课就去掉 4 小时。
- 每分钟排程（PAGE 130–134）：每天开工时在专用本子上按小时画格，把工作时间全部划成块，最小 30 分钟，杂事合并成"任务块"并在页边列明细。估时不准或被打断时，下一个空隙就为剩余时间重排，一天重排六次也正常。三个稳定技巧：初期会系统性低估耗时，要保守；不确定的任务后面跟一个"溢出条件块"（没做完就续上，做完就做预定的杂事）；多放任务块接住突发事项。若出现重要灵感，可以推翻当天剩余计划，灵感用完再重排。作者的总结："It's the habit of asking that returns results"（有价值的是不断追问时间怎么用，而不是死守答案）。
- 量化深度（PAGE 134–136）：问"培训一个没有专业背景的聪明应届生多少个月能接手这件事？"——编辑学术论文约 50–75 个月（深），季度销售 PPT 约 2 个月，项目状态会议约 3 个月（浅）。偏向月数高的任务。
- 浅层预算（PAGE 136–138）：和老板谈"我的时间里浅层工作应占多少"，多数非入门岗位答案在 30%–50%；然后守住它——拒绝浅层味重的项目、把周例会改为"有进展再聊"、早上更多时间断开通信。和老板谈的好处是拿到组织认可，下次拒绝有依据。自雇者自己定比例。若老板答"需要多少浅层就做多少"，说明这份工作不支持深度，作者建议开始规划转岗；入门级员工应推迟这一步。
- 五点半前收工（PAGE 138–142）：先定死不工作的时间，再倒推规则。Nagpal 定每周 50 小时、每年只出差 5 次、限制审稿数量，按期拿到终身教职。作者慎说"好"；拒绝时态度明确、理由模糊（"日程冲突，去不了"），不给"那我帮你看看方案"这类安慰奖。固定下班点会制造稀缺感，让默认答案变成"不"，也会测出老板深夜发邮件其实并不要求即时回复。
- 邮件（PAGE 145–148）：回复前先想清"这封邮件代表什么项目、用最少来回怎样走完"，一次写清流程、当前步骤和下一步（如约咖啡直接给出两天各三个时段，"你回哪个就算确认"）。
- 停工仪式（PAGE 84–91）：收工后不允许任何工作侵入，包括看邮件和浏览工作网站。作者的步骤：最后看一眼收件箱有无当日必须回复的；把脑中和纸上的新任务转进正式任务清单；快速扫一遍所有清单，看未来几天日历；据此粗排明天；最后说一句固定的"停工完成"口令。每天多花 10–15 分钟，约 1–2 周后大脑才会信任它。作者的格言："When you work, work hard. When you're done, be done."（工作时全力，收工就彻底收工）。

### I（Interpretation，白话）
浅层工作的危害常被低估、重要性常被高估，因为每件小事单看都"挺合理"。只有把一周加总、算出比例，才看得见代价。先用"应届生月数"分出深浅，再给浅层定上限、给一天定终点，你就被迫做取舍。时间块不是为了把自己捆死，而是逼自己隔一会儿就问一次"剩下的时间怎么用最好"。停工仪式让你不必靠脑子记住所有未完成的事，清单替你记着，下班后才能真的停下来。

### A1（书中应用，转述）
- 作者：2011–2014 年在乔治城大学几乎不在晚上和周末工作，发表约 20 篇论文、拿到两项竞争性基金、写了一本书（PAGE 139）；对比同行"Tom"一天 12 小时只有 1.5 小时做"真正的研究"（PAGE 139）。
- Nagpal：从早 7 点到半夜见缝插针 → 定每周 50 小时上限，配额压缩出差与审稿，提前拿到正教授（PAGE 139–140）。
- 37signals：夏季四天工作周后产出不减，被砍掉的主要是浅层工作（PAGE 127–128）。

### A2（未来触发场景）
1. 中层经理："一天五个会，晚上十点才开始写方案。" → 用应届生月数给会议打分，与上级谈浅层比例，把方案写作块排在上午、会议集中到下午。
2. 自由职业设计师："客户消息随时来，周末也停不下。" → 固定下班点 + 停工仪式；用流程式回复减少来回。
3. 研究生："导师随时找，我的实验总在晚上做。" → 先做时间盘点和时间块；预算谈话视师生关系谨慎处理，可用"本周深度/浅层小时数"数据开口。

### E（Execution，执行步骤）
1. **盘点与打分**：列出上周事项与时长，每项问"聪明应届生要培训几个月才能接手"，≤3 个月记为浅层，算出浅层占比。
   🔴 CHECKPOINT 1：用户是否看到了一个具体数字（如"上周浅层 68%"）？没有数字就不进入下一步。
2. **定预算与终点**：
   - 有上级：准备一句话开场——"我统计了上周，浅层工作约占 X%，你觉得我这个岗位多少比例合适？"拿到一个数字（通常 30%–50%）。
   - 自雇或无法谈：自己定一个比例。
   - 定一个固定下班时间，倒推 2–3 条配额（例：每周会议不超过 N 小时、每月外出活动不超过 M 次），准备一句干脆的拒绝话术，不附带安慰奖。
   🔴 CHECKPOINT 2：预算与下班点是否写下来了，且至少有一条配额？
3. **每天时间块**：开工时在纸上把工作时间全部划块（≥30 分钟），深度块先放，杂事合并进任务块；不确定的任务加溢出条件块；被打断就在下一个空隙重排剩余时间；有重要灵感可推翻计划。回邮件时用流程式写法：一次写清流程、当前步骤和下一步。
4. **停工仪式**（每天收工前 10–15 分钟，固定顺序）：看一眼收件箱有无今天必须回的 → 把散落的新任务收进一个清单 → 扫一遍所有清单和未来几天日历 → 粗排明天（可直接作为明天时间块的草稿）→ 说一句固定收工口令。之后不看工作消息；若脑中又冒出工作念头，提醒自己"已经在清单里了"。
5. **两周回看**：浅层占比是否下降、下班后被侵入次数是否减少。
   🔴 CHECKPOINT 3：调整依据是记录数据（占比、侵入次数），而不是"好像还是很忙"。

**如果这一步失败**

| 步骤 | 触发条件 | 一线修复 | 兜底 |
|---|---|---|---|
| 1 | 记不起上周做了什么 | 从本周起每天收工时记一行 | 只盘点"会议 + 消息"两类 |
| 2 | 老板回避或答"需要多少做多少" | 用数据换一种问法："如果砍掉一个会，你最先砍哪个？" | 说明这是岗位不支持深度的信号，长期考虑调整岗位；入门级先积累技能 |
| 2 | 担心拒绝影响关系 | 只先拒绝"应届生月数最低"的那一类 | 把拒绝改为延后（"下周四之后可以"） |
| 3 | 一天重排太多次而放弃 | 加长任务块、加溢出条件块，估时放宽 1.5 倍 | 只排上午，下午自由 |
| 4 | 下班后还是忍不住看消息 | 收工口令后把工作 App 退出登录 / 手机工作模式 | 留一个固定的晚间 10 分钟检查窗口，其余时间不看 |
| 4 | 仪式坚持不到一周 | 压缩为三步：收清单 → 排明天 → 口令 | 和用户约定只试 10 个工作日 |

### B（Boundaries，边界）
- **封顶不是清零**：浅层工作是工作的一部分，目标是控制占比，不是不回邮件、不开会。
- **自主度门槛**：入门级岗位、轮班、日程完全由他人决定的岗位，预算谈话不适用（作者明说入门级应推迟）；只保留停工仪式和轻量时间块，并承认结构性限制。
- **文化差异**：书中"理由模糊的拒绝""不回复"等做法在层级文化或客户服务型工作中代价不对称，需按用户处境调整；不鼓励冷处理同事或违反岗位职责。
- **学术偏差**：固定下班点的成功案例都来自教授，自主度高于多数岗位；先在小范围测试"老板深夜消息是否真要求即时回复"。
- **证据强度**：停工仪式的心理学依据多条存疑（见上）；时间块、预算、固定下班点是作者经验。对用户说"可以试两周看数据"。
- **不是组织改造**：本 skill 只给个人做法；团队会议文化、全员即时通讯规则需要组织层面讨论（多问题交织时可先用 maodun-fenxi 找主要矛盾）。
- **安全**：长期失眠、崩溃感、躯体症状 → 建议心理或医疗专业帮助；违法超时、欺凌 → 建议劳动维权渠道；出现自伤或自杀信号 → 立即停止，按 psyche 第五节危机话术回应。

## 💬 输出格式

给用户的回复按序：
1. 一句话复述用户的处境（用原话里的数字或场景）；
2. 用"应届生月数"给他提到的 2–3 件事打分，点出哪几件是浅层；
3. 给一个底线：浅层比例或固定下班点（二选一先做），附一句可直接说出口的话术；
4. 明天就能用的时间块草图（3–5 行）；
5. 停工仪式三到五步，含一句收工口令；
6. 一句证据提醒；
7. 全文只问 1 个问题。

**示例**（用户："一天开五个会，正事都拖到晚上十点才做，周末也在回消息。"）
```
一天五个会、正事拖到晚上十点，你的白天基本被切碎了。
先给这些事打个分：如果找一个聪明的应届生，周会大概培训三个月就能替你去，回群消息一两周，写方案恐怕要几年。前两类就是浅层工作。
建议先定一个下班点，比如 19:00，然后倒推：每周找出一个可以改成"有进展再同步"的会。跟领导可以这么说："我统计了一下，上周会议和消息占了我七成时间，哪些会您觉得我可以不去？"
明天的格子：9:00–11:00 写方案（不开消息），11:00–11:30 处理消息，下午集中开会，16:30–17:00 留作机动。
收工前 10 分钟：看一眼有没有今天必须回的 → 把散落的事收进一个清单 → 扫一遍清单和明后天日历 → 粗排明天 → 对自己说"今天收工"。之后不看工作群。
这些是作者和几位教授的经验，研究依据有限，先试两周看看晚上被打扰几次。
这五个会里，哪一个最可能换成书面同步？
```
