# Hexagram Situation Diagnosis

## R — 原文引用

### 开局与混沌
> 屯：元亨利贞。勿用有攸往，利建侯。（第三卦）
> 蒙：亨。匪我求童蒙，童蒙求我。初筮告，再三渎，渎则不告。利贞。（第四卦）
> 需：有孚，光亨，贞吉。利涉大川。（第五卦）

### 争端与组织
> 讼：有孚，窒惕，中吉，终凶。利见大人，不利涉大川。（第六卦）
> 师：贞，丈人吉，无咎。师出以律，否臧凶。（第七卦）

### 联盟与依附
> 比：吉。原筮元永贞，无咎。不宁方来，后夫凶。（第八卦）

### 通塞与转折
> 泰：小往大来，吉亨。（第十一卦）
> 否：否之匪人，不利君子贞，大往小来。（第十二卦）

### 剥落与回归
> 剥：不利有攸往。（第二十三卦）
> 复：亨。出入无疾，朋来无咎。反复其道，七日来复，利有攸往。（第二十四卦）

### 受困与革新
> 困：亨，贞，大人吉，无咎，有言不信。（第四十七卦）
> 革：已日乃孚，元亨利贞，悔亡。（第四十九卦）
> 鼎：元吉，亨。（第五十卦）

### 完成前后的风险
> 既济：亨，小利贞，初吉终乱。（第六十三卦）
> 未济：亨，小狐汔济，濡其尾，无攸利。（第六十四卦）

### 危机与响应
> 履：履虎尾，不咥人，亨。（第十卦）
> 震：亨。震来虩虩，笑言哑哑。震惊百里，不丧匕鬯。（第五十一卦）

### 积累与释放
> 小畜：亨。密云不雨，自我西郊。（第九卦）
> 大畜：利贞，不家食吉，利涉大川。（第二十六卦）

### 涣散与节制
> 涣：亨。王假有庙，利涉大川，利贞。（第五十九卦）
> 节：亨。苦节不可贞。（第六十卦）

## I — 方法论骨架

《周易》的第一层用法是"处境命名"：不要急着给行动建议，先判断问题属于哪类局面。

**局面分类速查表**：

| 局面类型 | 卦象 | 中心矛盾 |
|---------|------|---------|
| 开局混沌 | 屯 | 秩序未立却想推进 |
| 认知未开 | 蒙 | 需要启蒙但要保持求教者主动 |
| 等待/蓄积 | 需、小畜、大畜 | 条件未成熟，需要等待或积累 |
| 争端 | 讼 | 有理可争，拉到底会双输 |
| 组织动员 | 师 | 有目标需要组织力量，必须有纪律 |
| 结盟依附 | 比 | 需要拉拢或加入，但时机和选择关键 |
| 通泰/闭塞 | 泰、否 | 顺境中暗藏反转，逆境中孕育转机 |
| 基础剥落 | 剥 | 底层结构在崩溃，不宜扩张 |
| 回归正轨 | 复 | 从偏离中返回，有修复窗口 |
| 受阻困境 | 困 | 被卡住，有言不信，需要内部突破 |
| 改革/新建 | 革、鼎 | 旧制需革，新制要能承载 |
| 已完成/未完成 | 既济、未济 | 已成有尾部风险，未成有临门风险 |
| 涉险行走 | 履 | 在危险中谨慎行动 |
| 突发冲击 | 震 | 突发事件，需要稳住核心 |
| 涣散重组 | 涣、节 | 组织涣散后重组，需要设边界 |

## A1 — 源文件应用案例

### 案例 1：屯卦 — 开局混乱不是无能
- **文本**："勿用有攸往，利建侯。"
- **解读**：禁止大推进，允许建组织。初创阶段最大的错误是把"缺乏秩序"当"需要提速"。
- **应用**：新项目初期混乱时，先建立组织、规则、负责人，再推进。

### 案例 2：讼卦 — 争端有上限
- **文本**："中吉，终凶。"
- **解读**：在合理范围内处理争端有益，但拉到底会破坏所有关系。
- **应用**：纠纷中先确定止争点——赢了什么算"中吉"，什么情况必须退出。

### 案例 3：泰否 — 通塞是同一枚硬币
- **文本**：泰"小往大来"，否"大往小来"。
- **解读**：通泰时小代价换大回报，闭塞时大投入只能换小产出。两者互为反面。
- **应用**：判断当前是通泰期（可以以小博大）还是否塞期（要减少投入、守正待时）。

### 案例 4：剥复 — 衰败和回归要区分
- **文本**：剥"不利有攸往"，复"出入无疾，朋来无咎"。
- **解读**：剥落期不能推进；复归期可以稳定重建。
- **应用**：面对困难，先判断是"还在剥"（该收缩）还是"已经复"（可重建）。

### 案例 5：既济未济 — 完成和未完成都有风险
- **文本**：既济"初吉终乱"，未济"小狐汔济，濡其尾"。
- **解读**：完成后最怕松懈（初吉终乱）；未完成最怕功亏一篑（濡其尾）。
- **应用**：项目接近完成时警惕尾部风险；项目迟迟不完时检查是否就差最后一步。

## A2 — 触发场景

### 适合触发的场景
1. 用户描述复杂局面，希望用《周易》分类整理。
2. 用户不知道该推进、等待、修复、结盟还是止损。
3. 用户已有卦名，需要对应到现实问题类型。
4. 用户说"局面像哪一卦"、"帮我诊断处境"。

### 不适合触发的场景
1. 用户要求随机起卦、算命、预测未来。
2. 用户只需要原文翻译。
3. 高风险法律/医疗/财务问题替代专业意见。

## E — 执行步骤

### 模板：处境诊断表

| 检查项 | 你的回答（选项） | → 自动判定 |
|--------|---------------|-----------|
| 你要做的这件事规模多大？ | 小事/试点 / 中等/标准 / 大事/大投入 / 涉大川/巨变 | → 决定卦簇范围 |
| 当前的压力来自哪里？ | 外部环境 / 内部组织 / 人际冲突 / 资源不足 / 规则缺失 / 突发冲击 | → 对应卦簇方向 |
| 秩序/规则是否已建立？ | 已建立 / 建立中 / 混乱未立 | 未立→屯；建立中→需/小畜 |
| 你处于什么阶段？ | 刚起步 / 中段推进 / 接近完成 / 已完成 / 已过头 | → 对应既济/未济/亢龙判断 |
| 最主要的阻塞/卡点是什么？ | 信息不够 / 资源不够 / 阻力太大 / 规则不清 / 人心散了 / 被卡住 | → 锁定核心卦象 |
| 你最倾向做的动作是？ | 推 / 等 / 退 / 求助 / 重组 / 改革 | 主观倾向 → 用于检测是否与客观卦象矛盾 |

**推导规则**：第 3-5 项锁定主导卦象（15 种局面之一），第 6 项检测主观倾向与客观处境是否冲突（如「在屯卦却想推大川」= 危险误判）。

### 步骤

1. **填表诊断**：输出 `主导处境：[卦名] | 中心矛盾：[X] | 最危险误判：[Y]`（Y 来自主观倾向与客观卦象的冲突）
2. **匹配候选卦象**：给出 2-3 个候选局面，说明为什么主导卦象比其他的更贴切。
   🔴 **CHECKPOINT**：展示诊断+候选对比，等待确认。
3. **输出诊断卡**：
   ```
   卦象：[X] | 阶段：[初/中/末]
   核心张力：[A vs B]
   推荐 skill：[Y]
   不推荐动作：[Z]
   不确定性：[高/中/低]
   ```
4. 🛑 **STOP**：诊断卡输出后不自行调用其他 skill，等用户确认。

## B — 边界与 Fallback

### 失败模式
- 把任何困难都说成"困卦"，失去区分度。
- 只按用户情绪选卦，不按事实结构。
- 给出卦名后立刻下结论，不说明证据。

### Fallback（if-then 三段式）

| 触发条件 | 一线修复 | 仍失败 → 兜底 |
|---------|---------|-------------|
| 把所有困难都说成"困卦"，失去区分度 | 困卦应有"困而不失其所"的核心特征。没有这个特征 → 不是困卦，重新对焦 | 候选卦象全是负面卦 → 查每个卦的"利"面。困有亨，剥有硕果不食。补一条：此局面下最小的正向可行动作 |
| 候选卦象匹配多个，用户困惑 | 不强制选一。给 2-3 个候选，标注各自侧重什么矛盾。让用户按"哪个矛盾最困扰我"选 | 用户也选不出 → 用排除法："目前最不困扰你的矛盾是哪个？先排除。剩下两个对比" |
| 诊断后用户直接要行动建议 | 不直接给。诊断完成 → 推荐下一步应调用的 skill → 形成"诊断 X → 行动 Y"闭环 | 用户拒绝再调另一个 skill → 给一个最保守的单步动作 + 一句警告"不做完整分析前，这个动作只走一步" |
| 只按用户情绪选卦，不按事实结构 | 卦象分类判断后，对比用户情绪偏向。如果情绪卦和事实卦不同 → 先呈现事实卦，再解释"你感觉像 X，但实际结构更像 Y" | 用户坚持情绪卦 → 接受："你感受到的是 X 的局面。但请注意，按照实际情况，这个局面的出口在 Y 方向上" |
| 给出卦名后立刻下结论，不说明证据 | 强制停顿：命名后 → 列举至少 3 个匹配证据 → 才给结论 | 证据不足 3 个 → 标注"低置信度分类"，给出 2 个最可能的候选而非 1 个 |
| 用户提供了非常片面的信息（只说结果不说原因） | 不急着诊断。追问："导致这个结果的 2-3 个关键事件是什么？" | 用户也说不清关键事件 → 只做最宽泛的分类（进/退/守/变的处境类型），不做具体卦象命名 |

## 反例黑名单（dim9）

| # | 不要做的事 | 为什么 | 正确做法 |
|---|-----------|--------|---------|
| 1 | 把任何困难都说成"困卦"，失去区分度 | 困卦有特定结构（有言不信/内部突破），不是所有困难都是困 | 先跑一遍局面分类速查表，至少给出 2-3 个候选而非直接判困 |
| 2 | 只按用户情绪选卦，不按事实结构 | 用户说"我感觉被困住了"≠事实上是困卦 | 用 Step 1 收集客观事实（目标/压力源/参与者/资源）再匹配 |
| 3 | 给出卦名后立刻下结论，不说明匹配证据 | 说"你这是屯卦"不等于用户理解为什么是屯 | 每个诊断必须附带匹配理由：为什么屯而不是蒙/需？ |
| 4 | 候选全是负面卦，让用户绝望 | 困卦也有"困而不失其所"，剥卦上九"硕果不食"是保留种子 | 每次诊断至少提一条该卦的"利"面或正向动作 |
| 5 | 诊断后直接给行动建议而不推荐下一步 skill | 诊断→行动应形成闭环，不应在诊断 skill 内越界 | 输出"推荐下一步调用 X skill"而非直接给行动方案 |
