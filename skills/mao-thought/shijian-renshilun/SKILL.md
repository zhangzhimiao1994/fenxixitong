## 🧭 决策树（快速路由）

```
用户表现出"分析瘫痪"或"盲目行动"
│
├── 高风险一次性不可逆决策？ → ❌ 不触发，必须充分准备后一次性做好
├── 已有成熟SOP且有效运转？ → ❌ 不触发，直接学习成熟方法
├── 纯理论/学术研究？ → ❌ 不触发
│
└── 陷入行动-认知循环问题 → ✅ 激活本skill
    │
    ├── "不敢动，要再研究研究" → 缺乏感性认识(A) → 步骤2设计MVP
    ├── "做了很多但不总结" → 有感性未提炼(B) → 步骤2安排复盘
    ├── "理论都懂但落不了地" → 有理性未验证(C) → 步骤2制定验证计划
    └── "迭代了但没突破" → 已过一轮需螺旋升级(D) → 步骤3进入下一轮
```

## 🔄 三步流程

```
步骤1: 诊断当前循环位置         步骤2: 推动飞跃                  步骤3: 螺旋升级
┌──────────────────┐      ┌──────────────────┐      ┌──────────────────┐
│ 输入: 用户当前状态描述 │       │ 输入: 阶段诊断(A/B/C/D) │       │ 输入: 本轮飞跃结果    │
│ 动作: 四象限定位      │  ──→  │ 动作: 按阶段执行关键动作 │  ──→  │ 动作: 标注新认知+设计下轮 │
│ 输出: 阶段诊断       │       │ 输出: 飞跃行动记录+结果   │       │ 输出: 第N轮循环总结    │
│ 🔴 CHECKPOINT 1    │      │ 🔴 CHECKPOINT 2        │      │ 🔴 CHECKPOINT 3     │
└──────────────────┘      └──────────────────┘      └──────────────────┘
```

## 核心概念：认识的两个飞跃

> "你要知道梨子的滋味，你就得变革梨子，亲口吃一吃。" — 《实践论》

```
感性认识 ──[第一次飞跃：去粗取精]──→ 理性认识 ──[第二次飞跃：回到实践验证]──→ 螺旋升级
 (表面/片面)                           (本质/规律)                            (新认知)
```

两个常见错误：
- **经验主义(ce02)**：停在感性阶段——做了但不总结
- **教条主义(ce01)**：停在理性阶段——研究了但不行动

---

## 📋 步骤1：诊断当前循环位置

**输入**：用户当前状态描述。

**动作**：用以下四象限诊断——

| 位置 | 感性认识（实践） | 理性认识（总结） | 典型症状 |
|------|:---:|:---:|------|
| A — 缺乏感性 | ❌ | ❌ | "不敢开始""再研究研究" |
| B — 有感性未提炼 | ✅ | ❌ | "做了很多但不总结""重复犯同样错误" |
| C — 有理性未验证 | ❌ | ✅ | "理论都懂但没落地""方案完美但数据没变化" |
| D — 需要螺旋升级 | ✅ | ✅ | "迭代了但没有突破""每次改的都是表面" |

**输出**："当前处于___阶段（A/B/C/D）。诊断依据：___。下一步应该：___。"

🔴 **CHECKPOINT 1**：是否明确了A/B/C/D中的哪一个？如果判断为D但实际可能是B（假性完成循环），要警惕——用户说的"总结过了"可能只是浅层复盘。

### 如果步骤1失败

| 触发条件 | 一线修复 | 仍失败则兜底 |
|---------|---------|------------|
| 四象限无法定位（兼具ABC特征） | 问："你上一次真正动手做这件事是什么时候？做完后有没有写过复盘文档？" 根据回答锁定 | 如果完全无法定位，退一步：先要求做一次最小实践作为基线 |
| 用户声称是D但产出质量无提升 | 追问："最近3次迭代，有哪些核心假设被推翻了？" 如果答不出 → 其实是B | 按B处理：安排复盘提炼 |
| 用户说"我不确定" | 逐一排查四个象限的排除法——"有没有做过？（排除A）有没有总结过？（排除B）..." | — |

---

## 📋 步骤2：推动飞跃（执行关键动作）

**输入**：步骤1产出的阶段诊断（A/B/C/D）。

**动作**：按阶段执行——

**如果处于A（缺乏感性认识）**：
- 设计"最小可行实践"——3天内可以完成的最小动作，确保获得一手体验
- 例如：不是做完整市场调研，而是约3个目标用户聊一聊
- 原则："先尝一口梨子，不要想着切一整盘水果拼盘"

**如果处于B（有感性未提炼）**：
- 安排复盘会，用"实事求是四步法"从经验中提炼规律
- 追问三个层级：①做了什么？②为什么有效/无效？③底层的规律是什么？
- 输出格式："我们从___经验中学到：___。验证标志：如果下次___出现，说明这个规律成立。"

**如果处于C（有理性未验证）**：
- 制定验证计划，把理论拿到实践中检验
- 必须设定"证伪条件"："如果___现象出现，说明理论正确；如果___出现，说明需要修正"
- 不设证伪条件的验证 = 自我欺骗

**如果处于D（需要螺旋升级）**：
- 标注"本轮新认知"——相比上一轮知道了什么新的东西
- 设计下一轮实践计划，重点验证新认知

**输出**：飞跃行动记录——"阶段___，关键动作：___，预期产出：___，验证标准：___。"

🔴 **CHECKPOINT 2**：C阶段的验证计划是否设定了"证伪条件"？如果没有证伪条件，这不是验证而是确认偏见。

### 如果步骤2失败

| 触发条件 | 一线修复 | 仍失败则兜底 |
|---------|---------|------------|
| A阶段：无法设计出3天内可完成的最小实践 | 缩小范围——不是"验证商业模式"而是"打10个电话" | 如果连最小动作都设计不出，说明问题定义本身有问题——回到更上游 |
| B阶段：复盘会变成流水账，提炼不出规律 | 换问法："如果让你给刚入职的新人一条最重要的建议，你会说什么？" 这往往就是规律 | 收集≥10条原始记录后定量分析，找频次最高的模式 |
| C阶段：实践结果与理论矛盾，用户不接受 | 这是关键检测点——"实践是检验真理的唯一标准"，矛盾时必须修改理论 | 如果用户坚持修改数据而非理论，标记为红灯：这不是技能问题而是决策者问题 |

---

## 📋 步骤3：螺旋升级

**输入**：步骤2产出的飞跃行动记录和结果。

**动作**：
1. 明确标注"本轮新认知"：相比上一轮，知道了什么新的东西？
2. 检查是否出现了新的矛盾或新的认知盲区
3. 设计下一轮的实践计划，重点验证本轮新认知

**输出**（第N轮循环总结模板）：
> "第N轮循环总结：
> 我们之前以为：___
> 实践证明：___
> 新的认知是：___
> 下一轮我们将验证：___"

🔴 **CHECKPOINT 3**：本轮总结是否包含了"之前以为 vs 实践证明"的对比？这个对比是螺旋上升的核心——没有推翻任何假设的循环不是真正的学习。

### 如果步骤3失败

| 触发条件 | 一线修复 | 仍失败则兜底 |
|---------|---------|------------|
| 循环了3轮但"新认知"都是表面调整 | 说明复盘深度不够——要求用5 Whys追问每个结论 | 如果3轮后仍无实质认知突破，暂停循环，回到步骤1重新诊断 |
| 新认知与旧认知矛盾 | 这是好事——认知升级的标志！记录矛盾点并设计专门验证 | 如果矛盾无法验证（纯观点冲突），需要第三方数据介入 |
| 无法设计下一轮实践 | 这是D→A的退化——重新从最小实践开始 | — |

## 🔴 红灯场景（立即停止使用本skill）

1. **高风险一次性决策**：并购、重大投资等不可逆决策——不能"先试试再迭代"。
2. **生命/安全相关**：涉及人身安全的操作不能实践-出错-迭代。
3. **用户拒绝接受实践的反驳**：当实践结果与理论矛盾，用户选择修改数据而非修正理论——这不是认知循环问题，是诚信问题。

---

## ⚠️ 作者盲点

毛泽东强调"实践是检验真理的标准"，但在大跃进时期不尊重实践反馈——当实践结果与理论矛盾时，选择了修改数据而非修正理论。教训：
- 实践认识论的有效性取决于你真的愿意接受实践的否定性结论。
- 如果做了3轮循环仍然没有推翻任何假设，要么没做真正的实践，要么在自欺欺人。

## 🧪 测试用例

### Test 1：分析瘫痪
> "我想创业做AI穿搭，但不懂服装行业，要先花3个月研究完再做。"

激活 → 步骤1诊断：A（缺乏感性认识）→ 步骤2设计MVP："本周内约3个朋友，用现有AI工具帮他们搭配3套，拍照记录反馈" → 步骤3设定下一轮验证方向。

### Test 2：盲目执行
> "我们做了12次A/B测试，每次改了按钮位置和颜色，转化率没变化。"

激活 → 步骤1诊断：D→B（假性螺旋，实际是做了没提炼）→ 步骤2复盘："12次测试中，有哪些假设被推翻了？如果都没有，说明测试设计本身有问题——不是按钮位置问题" → 步骤3螺旋升级：改测试方法而非继续微调。

### Test 3：理论与实践脱节
> "学了OKR、精益创业、设计思维一大堆方法论，团队落地一团糟。"

激活 → 步骤1诊断：C（有理性未验证）→ 步骤2设计验证："选一种方法论，在1个小组试点1个迭代周期。证伪条件：如果试点组的产出/速度低于对照组，说明这套方法不适用当前团队" → 步骤3总结。
