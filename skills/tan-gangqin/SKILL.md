## 🧭 决策树（快速路由）

```
用户描述"太多事要做"
│
├── 生存危机（资金链断裂/核心产品崩了）？ → ❌ 不是弹钢琴——用集中优势兵力，所有指头停下来只做一件事
├── 极早期（0-3人团队）？ → ❌ 没有十个指头要协调
├── 高度标准化重复执行（工厂/客服中心）？ → ❌ SOP比弹钢琴有效
│
└── ≥5项重要工作且无法取舍 → ✅ 激活本skill
    │
    ├── 所有目标都是P0、无法说"只做哪件"？ → 步骤1强制排序
    ├── 知道中心工作但其他工作被完全搁置了？ → 步骤2设定最低维持节奏
    └── 中心工作完成后团队失去方向？ → 步骤3建立切换机制
```

## 🔄 三步流程

```
步骤1: 确定唯一中心工作          步骤2: 非中心工作设最低节奏       步骤3: 建立节奏切换机制
┌───────────────────┐     ┌──────────────────────┐     ┌──────────────────────┐
│ 输入: 所有重要工作列表│      │ 输入: 中心工作+非中心工作列表 │      │ 输入: 当前节奏运行状态    │
│ 动作: 强制排序+矛盾验证│ ──→ │ 动作: 每项设定最低维持投入   │ ──→ │ 动作: 设定完成标志+切换触发 │
│ 输出: 唯一中心工作     │      │ 输出: 最低维持节奏表        │      │ 输出: 节奏切换方案       │
│ 🔴 CHECKPOINT 1     │     │ 🔴 CHECKPOINT 2         │     │ 🔴 CHECKPOINT 3       │
└───────────────────┘     └──────────────────────┘     └──────────────────────┘
```

## 核心隐喻

> "弹钢琴要十个指头都动作，不能有的动，有的不动。但是，十个指头同时都按下去，那也不成调子。"
> — 《党委会的工作方法》(1949)

| 隐喻元素 | 管理含义 |
|---------|---------|
| 十个指头 | 所有需要关注的重要工作领域（产品/销售/技术/团队/财务/合规...） |
| 都动作 | 每项工作都不能停摆，都有最低维持节奏 |
| 不能同时按 | 同一时期只有一个中心工作（主旋律），不能所有都是P0 |
| 有节奏配合 | 中心工作最强音，次要工作和声，搁置工作休止符 |
| 曲目切换 | 一个阶段完成后，中心工作切换，节奏变化 |

---

## 📋 步骤1：确定当前阶段的唯一中心工作

**输入**：当前所有需要做的重要工作（用户罗列 ≥5项，≤10项）。

**动作**：
1. 强制排序：问"如果只能做一件事，做哪件？"——被选出的就是中心工作。
2. 矛盾验证：中心工作是否与当前阶段的主要矛盾一致？（用矛盾分析法交叉验证：主要矛盾 = 中心工作）
3. 对每一项非中心工作标记为"第二位"或"第三位"。

**检查**：
- 如果中心工作每周都在变 → 实际上没有中心，比没有更糟糕
- 如果有 ≥2 个工作被标记为"并列第一" → 违反了"一个中心"硬约束，必须继续拆解

**输出**：
> "本阶段中心工作：___（唯一）。第二位工作：___。第三位工作：___。该中心工作对应的主要矛盾是：___。"

🔴 **CHECKPOINT 1**：中心工作是否唯一？是否通过了"如果只能做一件事"的测试？是否与矛盾分析一致？

### 如果步骤1失败

| 触发条件 | 一线修复 | 仍失败则兜底 |
|---------|---------|------------|
| 用户说"每件都重要，无法排序" | 用"T恤尺码法"：如果每项失败了会怎样？按失败后果严重程度排序 | 如果仍然无法排序，说明不是优先级问题而是信息不足——先用矛盾分析法找主要矛盾 |
| 中心工作每天都在变 | 用最近30天的时间分配反推——你实际花了最多时间在什么上？那个就是你的实际中心工作 | 如果实际中心与名义中心不一致，先解决这个矛盾 |
| 中心工作与矛盾分析判断不一致 | 检查是排序错误还是矛盾分析错误——两个独立方法交叉验证 | 如果结论矛盾且无法调和，优先相信矛盾分析（因为是系统性框架） |

---

## 📋 步骤2：为非中心工作设定最低维持节奏

**输入**：步骤1产出的中心工作 + 非中心工作列表。

**动作**：对每项非中心工作——
1. 定义"完全停摆会出问题的基线"：如果完全不做，多久会出问题？
2. 根据基线设定"最低维持投入"——每周/每月花多少时间和资源，确保不停摆
3. 按重要度分配时间比例：
   - 中心工作：50-60%
   - 第二位工作：20-30%
   - 第三位工作：10-20%

**输出**（最低维持节奏表）：
```
| 工作项    | 优先级 | 时间占比 | 最低维持动作               | 频率          |
|----------|--------|---------|--------------------------|--------------|
| ___      | 中心   | 55%     | 全力推进                   | 每日          |
| ___      | 第二   | 25%     | ___                       | 每周          |
| ___      | 第三   | 15%     | ___                       | 每月          |
| ___      | 第三   | 5%      | ___                       | 每月          |
```

🔴 **CHECKPOINT 2**：每项非中心工作是否都有"最低维持动作+频率"？是否存在某项目前投入为0且无计划的情况？

### 如果步骤2失败

| 触发条件 | 一线修复 | 仍失败则兜底 |
|---------|---------|------------|
| 某项非中心工作的最低维持投入看起来不可能安排 | 可能是优先级排错了——重新评估它是否真的是"不能停"的工作 | 如果确实必不可少但没时间，说明人手不够——这不是弹钢琴问题而是资源问题 |
| 非中心工作的最低维持也在被挤压 | 检查中心工作是否真的需要那么高投入——是否在微观管理？"领导者在弹琴不是在弹每个键" | 如果确实需要，说明当前中心工作的执行方式有问题——拆分或授权 |
| 某项工作"最低维持"定义不清 | 问："如果完全不做这项工作，3个月后会发生什么？" 根据后果反推底线 | — |

---

## 📋 步骤3：建立节奏切换机制

**输入**：步骤2产出的最低维持节奏表 + 当前阶段运行状态。

**动作**：
1. 为中心工作设定"完成标志"——达到什么标准算完成？
2. 设定切换触发器——一旦完成，立即执行以下动作：
   - 用矛盾分析法判断新的主要矛盾
   - 确定新的中心工作
   - 调整非中心工作的优先级和最低维持节奏
3. 设定"节奏审计"节点——每月检查一次：中心工作还在正确的轨道上吗？

**输出**（节奏切换方案）：
> "当前中心工作完成标志：___。完成后新中心工作候选：___→___→___（优先级递减）。下次节奏审计：___。"

🔴 **CHECKPOINT 3**：完成标志是否可验证（非模糊）？是否有新中心工作候选？是否有定期审计？

### 如果步骤3失败

| 触发条件 | 一线修复 | 仍失败则兜底 |
|---------|---------|------------|
| 完成标志模糊（"产品做好了就行"） | 拆解为可验证的量化标志——"核心功能上线+用户留存率≥X%" | 至少给出3条可观测的完成信号 |
| 切换后新中心与旧中心差距太大 | 这是正常的——不同阶段中心不同。用矛盾分析法验证新中心是否正确 | 如果新旧中心完全无关，检查是否在跳跃性决策 |
| 节奏审计发现中心工作总是跑偏 | 说明中心工作的确定有根本问题——回到步骤1，同时检查是否外部环境发生了变化 | 如果连续2次审计都跑偏，重新运行整个流程 |

## 🚫 反例与黑名单

| # | 反模式 | 描述 | 纠正 |
|---|--------|------|------|
| ce04 | 六路分兵 | 嘴上说十个指头都动，实际是没有中心工作的资源分散——"全线出击" | 强制只选一个中心工作 |
| — | 中心工作频繁切换 | 每周甚至每天换"中心工作"——比没有中心更糟糕，团队永远在适应中消耗 | 中心工作的周期至少是一个月（季度为佳） |
| — | 非中心长期为零 | 冲刺中心工作时把其他全停了——技术债/团队建设/客户关系积压后爆发 | 每个非中心都有最低维持动作 |
| — | 领导亲自弹所有键 | 领导者定节奏、团队成员各弹各的声部——微观管理=钢琴家用脚弹琴 | 节奏归领导，执行归团队 |
| — | 全面发展陷阱 | 用"十个指头都要动"为不做取舍找借口 | 十个指头都要动 ≠ 没有主旋律 |

## 🔴 红灯场景（立即停止使用本skill）

1. **生存危机**：公司面临生死存亡——所有指头停下来，只做一件事（活下去）。用集中优势兵力。
2. **中心工作=团队规模时**：如果唯一的中心工作是"招人/扩团队"，这是一个危险信号——说明可能没有真正的业务中心。
3. **连续3个月中心工作都没有完成标志触发**：说明中心工作可能设定错误，或者团队执行力有根本问题——重新评估。

---

## ⚠️ 作者盲点

- 毛泽东默认领导者能正确判断中心工作——但在商业环境中，"什么最重要"往往是最难回答的问题。必须配合矛盾分析法来确定。
- "一个时期"的粒度模糊——月度、季度还是年度？建议：日常运营用月，战略方向用季，年度规划用年。

## 🧪 测试用例

### Test 1：所有目标都是P0
> "Q3我们有5个目标：新产品上线、获客提升30%、技术债偿还、团队扩充到40人、融资B轮——每个都标了P0。"

激活 → 步骤1强制排序："如果只能做一件" → 融资B轮（没有钱其他都是空谈）→ 步骤2设定其他4项最低维持：新产品保持研发（不能停但不必全速）、获客维持当前水平、技术债每两周1天、招人暂缓→ 步骤3设定：融资close后新中心工作是新产品上线。

### Test 2：重要工作被长期忽视
> "我们全力冲刺产品发布3个月了，代码质量一塌糊涂、团队有人想离职、客户也没人维护。"

激活 → 步骤1诊断：中心工作（产品发布）没问题，但非中心工作投入已经逼近零 → 步骤2为技术债/团队/客户关系设定最低维持：每周至少半天代码review、每人至少1次1:1、重点客户每周1次联系 → 步骤3设定产品发布完成后的下一阶段中心。

### Test 3：阶段切换后迷失
> "上一季度冲刺完了，产品上线了，现在团队闲下来不知道该干什么。"

激活 → 步骤1：新产品上线后，用矛盾分析法判断新主要矛盾——可能是"产品有了但用户不来" → 新中心工作：获客 → 步骤2重新排优先级 → 步骤3设定获客阶段完成标志。

## 🔗 跨 skill 协作链

- **矛盾分析法** (composes-with)：弹钢琴需要确定中心工作，矛盾分析法提供判断——主要矛盾 = 中心工作。弹钢琴是节奏管理，矛盾分析法是确定主旋律的方法。
- **集中优势兵力** (composes-with)：生存危机时弹钢琴退场，集中优势兵力上场——所有指头停下来只做一件事。
