# 结构模型：自我-本我-超我

## 触发条件
- 用户在纠结两个以上的冲突需求
- 用户说「我不知道自己想要什么」或「我应该这样做但我不想」
- 用户在过度自我批评
- 用户在三种不同的要求之间被撕扯
- 触发词：「纠结」「应该但不想」「控制不住」「我在和自己打架」「不懂自己为什么这样」

## 不触发
- 简单的二元选择（只有一个冲突）
- 纯认知问题（没有情感层面的冲突）
- 丧失后严重的自我谴责+低价值感 → `freud-mourning-melancholia`（自尊已受损，不只是冲突）
- 持续的焦虑+回避行为+「我不知道怕什么」→ `freud-anxiety-defense`（焦虑是主角，冲突是配角）

## 模型

自我（Ego）同时为三个主人服务：
1. **本我（Id）**：「我要这个，现在就要」——遵循快乐原则
2. **超我（Super-ego）**：「你不应该/不配」——被内化的父母/权威的声音
3. **外部现实**：「不能这样做，有后果」

健康 = 自我能成功谈判三方
症状（焦虑/抑郁/强迫）= 自我无法谈判，崩溃或症状形成

## 执行步骤

### 第一步：三向拆解
让用户对他当前的困难回答三个问题：
1. 本我问题：「在这件事里，我真的想要什么？」（不要自我审查）
2. 超我问题：「我听到什么声音在告诉我应该怎么做？这个声音从哪来的？谁教的？」
3. 现实问题：「现实中我实际能做什么？选项是什么？」

### 第二步：辨别声音来源
当用户的超我声音特别响的时候，帮助辨别它属于哪个阶段：
- 父亲/母亲的声音？
- 学校/老师的规则？
- 领导/上级的要求？
- 社会/文化的期望？
→ 把这些外部的来源**命名**，使之不再是内在的无名恐怖

### 🔴 CHECKPOINT：超我来源确认
```
🔴 超我声音的源头 = [命名的外部来源]，用户确认这个追溯对不对？
- 对 → 继续第三步
- 不对/不准确 → 重新追溯，不跳过
确认？
```

### 第三步：重新分配权力
- 本我需求是合法的，应该被听到——给它一个安全出口（不是直接满足）
- 超我需求需要被**审查**——有些超我要求是不合理的过时规则，可以降级
- 现实限制是客观的——不要与之战斗，要与之谈判

### 第四步：最小可行方案
在三方中找到最小公分母：
- 「现在能做什么，既不完全背叛自己，也不会被现实彻底碾压？」
- 如果三方完全冲突→回归到最基本的生命维持（休息、吃饭、呼吸）

## 🔴 CHECKPOINT：三步后验证

在第一步「三向拆解」完成后，确认：
```
🔴 验证：本我需求 = [用户说的真正想要的东西]，超我声音来源 = [追溯到的外部来源]，确认？如果不对，重新回答本我/超我问题。
```

在第四步结束后，确认：
```
🔴 验证：最小可行方案 = [方案]，是否可行？如果做不到/更糟 → 降级到基础生命维持（休息、吃饭、呼吸），停止分析。
```

## 失败模式与 fallback

| 触发条件 | 一线修复 | 仍失败兜底 |
|---------|---------|-----------|
| 用户无法回答「本我真正想要什么」 | 改问：「如果你完全不需要对任何人交代——你最想做什么？」 | 跳过第一步，从第二步（追溯超我来源）开始 |
| 用户追溯不到超我来源 | 问：「谁第一个让你觉得自己不够好？」不限于父母——可能是老师/领导/伴侣 | → 如果仍无法追溯，降级为「基础自我关怀」方案（休息、吃饭、呼吸），不强行分析 |
| 三向完全冲突、最小方案也不可行 | 立即降级为「基础生命维持」——不推导解决方案 | → 建议休息后重新评估，或转 `freud-mourning-melancholia`（可能已进入忧郁） |
| 分析后用户感觉更糟 | 停止分析，确认：是释放后的正常波动，还是创伤被激活？ | → 如果是后者，转 `freud-trauma-hysteria` 的危险信号处理 |

## 诊断信号（用户的症状vs模型）

| 症状 | 可能的模型解释 |
|------|---------------|
| 失眠 | 三方的冲突在深夜持续进行→超我审查 或 本我要求浮现 |
| 疲劳但原因不明 | 自我在持续消耗能量做三方谈判 |
| 头痛/身体症状 | 被堵住的本我能量转化为躯体症状（癔症机制）|
| 过度自责 | 超我过度活跃，本我被审判 |
| 无法做出决定 | 自我被三方拉扯→失去谈判能力 |
| 食欲丧失 | 本我最基本的功能（吸收/接受）被超我压制 |

## 边界
- 此模型是心理动力的隐喻，不是脑科学的事实
- 如果用户显示出精神病性症状（现实检验失败），此模型不适用于自助
- 急性危机（自杀想法）→ 需要立即专业帮助，不是分析

## 反例黑名单 —— 不要做的事

1. **不要把三个声音的结论直接抛给用户「你就是超我太强」** —— 要通过提问让用户自己辨认声音来源
2. **不要在追溯超我来源时暗示「你父母害了你」** —— 超我来自内化过程，不是简单归咎
3. **不要在用户无法回答时强行推进** —— 如果用户「不知道想要什么」，这是信号不是失败，用退化问题
4. **不要把「最小可行方案」包装成「解决方案」** —— 这是临时休战协议，不是永久和平
5. **不要在用户出现躯体化症状时只用结构模型分析** —— 身体信号可能需要 `freud-trauma-hysteria`

## 自检脚本

在完成每一步后执行以下自检（用 ✅ / ⚠️ / ❌ 标注）：

```
[ ] 第一步：用户能否说出本我需求？（能=✅，需退化问题=⚠️，不能=❌转fallback）
[ ] 第二步：超我来源是否被追溯并命名？（是且用户确认=✅，追溯不准=⚠️，追溯不到=❌转fallback）
[ ] CHECKPOINT: 超我来源确认通过？（是=✅）
[ ] 第三步：三方需求是否都被识别？（是=✅，缺一方=⚠️补充）
[ ] 第四步：最小可行方案是否产出？（有方案且用户认可=✅，方案不可行=⚠️降级，无方案=❌转fallback）
[ ] CHECKPOINT: 三步后验证通过？（是=✅）
[ ] 全局：分析过程中用户是否变得更糟？（否=✅，出现波动=⚠️观察，创伤被激活=❌转trauma-hysteria）
```

**通过标准**：至少 5 项 ✅，无 ❌。如有 ❌，立即执行对应 fallback。
