## 🧭 决策树（快速路由）

```
用户说"问题太多了，不知道从哪里下手"
│
├── 问题已经明确且只有1个？ → ❌ 不触发本skill，直接执行
├── 紧急危机（着火状态）？ → ❌ 先灭火，危机后来用本skill复盘
├── 纯执行问题（修bug/走流程）？ → ❌ 不需要矛盾分析
│
└── ≥3个相互关联的问题交织？ → ✅ 激活本skill
    │
    ├── 能列出≥5条矛盾但无法判断优先级？→ 步骤1
    ├── 已列出矛盾但找不到"牵一发动全身"的那个？→ 步骤2
    └── 似乎找到了主要矛盾但不确定？→ 步骤3
```

## 🔄 三步流程

```
步骤1: 列举矛盾清单             步骤2: 判断主要矛盾             步骤3: 验证并追踪转化
┌─────────────────┐      ┌─────────────────────┐      ┌─────────────────────┐
│ 输入: 当前混乱局面描述  │       │ 输入: 矛盾清单(≥5条)    │       │ 输入: 候选主要矛盾       │
│ 动作: 逐条列出所有矛盾   │  ──→  │ 动作: 因果链追问        │  ──→  │ 动作: 反事实检验+阶段标记 │
│ 输出: 矛盾清单           │      │ 输出: 主要矛盾+理由      │       │ 输出: 一句话结论+转化条件 │
│ 🔴 CHECKPOINT 1        │      │ 🔴 CHECKPOINT 2        │      │ 🔴 CHECKPOINT 3        │
└─────────────────┘      └─────────────────────┘      └─────────────────────┘
```

## 📋 步骤1：列举矛盾清单

**输入**：当前混乱局面的完整描述（用户提供 + 追问补充）。

**动作**：
1. 列出当前局面中所有可见的矛盾/问题/张力，**不少于5条**，不急于排序。
2. 每条矛盾必须用"A与B之间的张力"格式表述。例如：
   - "产品体验与交付速度之间的张力"
   - "用户增长与盈利压力之间的张力"
3. 按维度分组检查是否遗漏：
   - 产品：功能完整度 vs 简洁性
   - 市场：增长 vs 盈利
   - 组织：人才密度 vs 扩张速度
   - 财务：投入 vs 产出
   - 外部：竞争力 vs 合规性

**输出**：矛盾清单，≥5条，每条以"A与B之间的张力"格式书写。

🔴 **CHECKPOINT 1**：矛盾清单是否≥5条？是否覆盖多维度？如果只有2-3条，说明用户描述不够——追加提问挖掘隐藏矛盾。

### 如果步骤1失败

| 触发条件 | 一线修复 | 仍失败则兜底 |
|---------|---------|------------|
| 想不出5条矛盾，脑中一片空白 | 逐个维度追问用户："产品方面有什么张力？市场方面？团队方面？" | 让用户描述最近3件最头疼的事，从中反向提炼矛盾 |
| 矛盾太抽象（如"业务不好"） | 追问："具体是什么跟什么在冲突？是供给跟不上需求，还是质量跟成本打架？" | 暂停分析，先收集具体事实数据再回来 |
| 用户说"就只有这一个问题" | 追问："这个问题里面，有没有不同维度的张力？表面是一件事，底层可能是几股力量的博弈" | 如果确认只有单一问题，退出本skill |

## 📋 步骤2：判断主要矛盾

**输入**：步骤1产出的矛盾清单。

**动作**：对每条矛盾执行因果链追问——
> "如果这个矛盾解决了，其他矛盾是否也会显著改善？"
> "如果这个矛盾恶化，其他矛盾是否也会跟着恶化？"

找到那个"牵一发而动全身"的瓶颈矛盾。判断标准：
- 它是其他矛盾的**上游因**而非下游果
- 解决它能让≥3个其他矛盾自动松动
- 它恶化了会让≥3个其他矛盾同时恶化

**输出**：一句判断结论——"主要矛盾是___，因为【因果链】___。"

🔴 **CHECKPOINT 2**：是否有清晰的因果链？如果不确定，进行反事实检验——"假设我们先忽略这个矛盾，去解决另一个，会怎样？"

### 如果步骤2失败

| 触发条件 | 一线修复 | 仍失败则兜底 |
|---------|---------|------------|
| 多条矛盾看起来同等重要，无法区分 | 用"上游/下游"标准重新判断——哪个矛盾在最上游？哪个是哪个的原因？ | 拆分过大的矛盾为更具体的子矛盾，重新分析 |
| 因果链不清晰 | 画因果图：列出每个矛盾之间的影响箭头（A→B表示A恶化导致B恶化），找箭头发出最多的那个 | 如果仍然不清晰，回到步骤1补充数据 |
| 选出的"主要矛盾"最终解决依赖外部不可控因素 | 该矛盾可能是症状而非根因——重新追溯它的上游 | 如实告知用户：当前信息不足以确定主要矛盾，建议收集XYZ数据后再判断 |

---

## 📋 步骤3：验证并追踪转化

**输入**：步骤2产出的候选主要矛盾。

**动作**：
1. **反事实检验**："如果我们忽略这个主要矛盾，先集中解决其他矛盾，会怎样？"——如果答案是"无法真正解决"，则判断正确。
2. **阶段性标记**：明确写出当前阶段的主要矛盾，并设定转化条件。
3. **复盘节点**：设定下一次重新评估的时间点（季度或每次重大变化后）。

**输出**（必须包含以下三要素）：
> "当前阶段的主要矛盾是___，解决它将使___等问题迎刃而解。预期该矛盾将在___条件下发生转化。建议下次复盘节点：___。"

🔴 **CHECKPOINT 3**：结论是否包含三要素（矛盾+影响+转化条件）？是否设定了复盘节点？

### 如果步骤3失败

| 触发条件 | 一线修复 | 仍失败则兜底 |
|---------|---------|------------|
| 反事实检验结论模糊（"可能能解决，可能不能"） | 至少模拟3个场景逐一检验——"先解决A不解决B：场景1___场景2___场景3___" | 说明该候选主要矛盾可能错误，回到步骤2重新判断 |
| 转化条件过于模糊（"市场变好了就行"） | 量化转化条件——"当___指标达到___数值时，我们认为主要矛盾转化" | 至少给出3个观测信号（即使无法量化） |
| 用户不接受判断结果 | 追问不接受的具体原因，可能是遗漏了某个矛盾 | 如果所有分析都被质疑，说明信息本身有问题——重新从步骤1开始 |

## 🔴 红灯场景（立即停止使用本skill）

1. **紧急危机**：服务器宕机、资金链断裂等——先灭火，危机后用本skill复盘。
2. **信息严重不足**：用户对本领域的了解不足以列出≥5条矛盾——先做信息收集而非矛盾分析。
3. **决策者缺位**：分析者没有决策权，分析完也无法推动——先确认谁有权决定再分析。

## ⚠️ 作者盲点

毛泽东晚年过于相信自己对"主要矛盾"的判断，忽视他人分析。教训：
- 主要矛盾的判断需要**至少2人独立分析后交叉验证**，不能由单一权威独断。
- 当实践结果与判断矛盾时，必须修改判断而非修改事实。

## 🧪 测试用例

### Test 1：多问题交织
> "公司同时有产品bug率上升、销售转化下降、工程师离职增加三个问题，不知道先解决哪个。"

激活本skill → 步骤1列举3个问题的矛盾本质 → 步骤2因果链追问：工程师离职→产品bug率上升→销售转化下降？→ 主要矛盾是团队稳定性 → 步骤3反事实检验。

### Test 2：方向争论
> "团队一半人说做ToB，一半人说做ToC，各有数据支撑，CEO也拿不定主意。"

激活 → 步骤1列举ToB vs ToC下的子矛盾 → 步骤2判断哪条矛盾是决策的核心瓶颈 → 步骤3输出转化条件。

### Test 3：阶段转换
> "以前靠投放驱动增长很有效，最近投放ROI持续下降，试了很多方法都不行。"

激活 → 步骤1列举旧模式与新现实的张力 → 步骤2判断核心矛盾是"渠道红利耗尽 vs 产品力不足" → 步骤3输出新阶段主要矛盾+转化条件。
